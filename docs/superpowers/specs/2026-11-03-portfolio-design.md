# JUWON — 포트폴리오 사이트 설계서

- 작성일: 2026-11-03
- 상태: 사용자 승인 대기 (대화에서 방향은 승인됨)

## 1. 목적과 성공 기준

**누가 보나**: 채용 담당자, 외주 클라이언트, 그리고 나를 소개하는 개인 공간.

**성공 기준**
1. 처음 들어온 사람이 10초 안에 "3D·AI 영상·그래픽을 하는 디자이너"라는 걸 안다.
2. 브라우저 탭 제목과 공유 미리보기 제목은 `JUWON — 3D · AI · Graphic Designer`.
3. 어느 화면에서든 한 번만 클릭하면 연락처(이메일, 인스타그램)에 닿는다.
4. 노션에 작업을 올리면 1시간 안에 사이트에 반영된다. 사이트를 따로 손댈 필요가 없다.
5. 휴대폰에서도 가로로 밀리는 화면 없이 모든 작업을 볼 수 있다.

**사용자가 정한 것**
- 내용 출처: 노션 페이지 "JUWON's ARCHIVES" (자동 연동)
- 메인 문구: 이름을 브랜드처럼 크게 쓴다 — `JUWON` + `3D · AI · GRAPHIC DESIGNER — BASED IN ILSAN, KOREA`
- 언어: 노션처럼 섞어서 쓴다. **헤더와 메인 텍스트는 무조건 영어**, 작업 설명은 노션에 쓴 그대로.
- 스타일 레퍼런스: Belen Jones, Dirt, AREA Technology, UNVEIL, CLOU Architects (recent.design)

**제가 추천으로 정한 것** (사용자가 "추천 방향으로 진행"이라고 함)
- 직접 만든 사이트 + 노션 공식 API 연동 + GitHub Pages 무료 호스팅
- 전화번호는 사이트에 싣지 않는다. 공개 사이트라 스팸 위험이 있고, 이메일과 인스타그램이면 연락하기에 충분하다. 원하면 설정 한 줄로 켤 수 있다.

레퍼런스 다섯 개의 공통점을 규칙으로 옮긴다. 상세 토큰은 저장소 루트의 `DESIGN.md`에
awesome-design-md 형식으로 기록한다.

| 배경 | 흰색 `#F7F7F5` 기본. 섹션에 따라 연한 파스텔(라벤더 `#E6E4F2`, 민트 `#E3EEE8`)로 바뀐다 |

## 3. 화면 구성

### ① Home (`/`)
- 위: 작은 알약 메뉴 — `WORKS` `ABOUT` `CONTACT`
- 가운데: 화면을 꽉 채우는 이름 **JUWON**. 바로 아래 작은 글씨(Geist Mono)로
  **3D · AI · GRAPHIC DESIGNER — BASED IN ILSAN, KOREA**.
  이름 위에는 크롬 3D 오브젝트가 겹쳐 떠 있고,
  마우스 위치에 따라 천천히 돈다. 휴대폰에서는 자동으로 천천히 돈다.
- 아래: 분야 이름이 큰 글씨로 줄지어 있다(Belen Jones 방식).
  `3D DESIGN / AI GENERATED / 2D GRAPHIC / TOUCHDESIGNER`
  - 마우스를 올리면 그 분야의 커버 이미지가 3D 오브젝트 표면에 비치고, 배경색이 그 분야의 파스텔로 바뀐다.
  - 클릭하면 그 작업의 상세 화면으로 간다.
- 맨 아래 작은 글씨: `ILSAN, KOREA` · 현재 시각(KST) · 이메일

### ② Works (`/works`)
- 위: 큰 제목 `WORKS` + 작업 개수
- 작업 카드가 **대각선으로 겹쳐 쌓여** 있다(UNVEIL 방식, CSS 3D 변형).
  스크롤하거나 화살표 키를 누르면 앞 카드가 넘어간다. 카드를 누르면 상세 화면으로 간다.
- 휴대폰(폭 768px 미만)에서는 세로 카드 목록이 된다.

**"작업 하나"의 단위**: 노션 Projects 표의 행 하나 = 작업 하나.
지금은 행이 분야별로 4개(3D 디자인, AI 생성, 2D, TouchDesigner)라서 카드도 4장이다.
행 안의 개별 작업(예: 리플리 EP, 임세모 VFX)은 상세 화면 안에서 차례로 보인다.
나중에 노션에 행을 더 만들면 카드도 그만큼 늘어난다.
카드가 4장뿐이라 분야 필터 버튼은 넣지 않는다. 카드가 12장을 넘으면 그때 태그 필터를 추가한다.

### ③ Work 상세 (`/works/[slug]`)
- 위: 영어 제목(크게) + 태그(알약) + 관련 링크
- 본문: 노션 페이지의 내용을 순서 그대로 보여 준다.
  - 이미지 → 화면 폭 가득
  - 노션에 올린 영상 → 자동 재생, 소리 꺼짐, 반복 재생, 컨트롤 표시
  - 임베드(YouTube, Vimeo, Instagram 등) → 그 서비스의 플레이어로 보여 준다
  - 글, 소제목, 목록, 구분선 → 그대로 보여 준다 (한국어 그대로)
- 아래: `← PREV` / `NEXT →` 와 `CONTACT` 버튼

### ④ About (`/about`)
- 큰 제목 `ABOUT`
- `EXPERIENCE` — 노션의 Education & Employment 목록 (최신순)
- `TOOLS` — 노션 Software 표에서 가져온다 (Photoshop, Illustrator, Cinema4D, Blender, After Effects, Figma, Daz 3D)
- `EXPERTISE` / `LANGUAGE` — 같은 표의 Expertise·Language 항목
- `CONTACT` — 이메일(누르면 메일 쓰기), 인스타그램 @baboyeonggaam, 지역

## 4. 노션 연동

### 데이터 흐름
```
노션 (공식 API)
   │  ① 동기화 스크립트 scripts/sync-notion.ts
   ▼
src/data/site.json   +   public/media/… (이미지·영상 파일 다운로드)
   │  ② 사이트 빌드 (Astro)
   ▼
정적 사이트 → GitHub Pages
```

사이트는 **`site.json` 하나만 읽는다.** 노션의 구조가 바뀌어도 동기화 스크립트만 고치면 되고,
화면 코드는 그대로 둘 수 있다.

### 노션에서 읽는 것
| 노션 위치 | 사이트에서 쓰는 곳 |
|---|---|
| Projects 표: `이름`, `태그`, `커버`, `관련 링크`, **`영문 제목`(새로 추가)** | Home 분야 목록, Works 카드, 상세 제목 |
| Projects 각 행의 페이지 본문 | Work 상세 본문 |
| 메인 페이지 왼쪽 칸의 Contact 항목 | Contact (전화번호는 제외) |
| 메인 페이지 왼쪽 칸의 Education & Employment 목록 | About › EXPERIENCE |
| Software·Expertise·Language 표 (`Name`, `Type`) | About › TOOLS / EXPERTISE / LANGUAGE |

### 영어 제목 규칙 (메인 텍스트는 무조건 영어)
1. `영문 제목` 칸에 값이 있으면 그 값을 대문자로 쓴다.
2. 비어 있으면 기본 이름표에서 찾는다: `3D 디자인 → 3D DESIGN`, `AI 생성 → AI GENERATED`, `2D → 2D GRAPHIC`, `TouchDesigner → TOUCHDESIGNER`
3. 둘 다 없으면 제목에서 영어·숫자만 남긴다. 그것도 비면 `UNTITLED 01`처럼 번호를 붙이고,
   동기화 로그에 "영문 제목을 채워 주세요"라고 경고를 남긴다.

주소(slug)도 영어 제목으로 만든다. 예: `/works/ai-generated`

### 파일 처리
- 노션 공식 API의 파일 주소는 1시간 뒤에 만료된다. 그래서 이미지와 영상은 **동기화할 때 내려받아** 사이트에 함께 올린다.
- 이미지는 웹용으로 줄인다(긴 변 2400px, WebP). 영상은 원본 그대로 둔다.
- 파일 하나가 95MB를 넘으면 GitHub Pages 한도(100MB) 때문에 올리지 않는다.
  그 자리에는 커버 이미지와 "노션에서 보기" 링크를 넣고, 로그에 경고를 남긴다.
- 파일 이름은 노션 블록 ID로 짓는다. 같은 파일을 다시 받지 않도록 캐시를 쓴다.

## 5. 자동 업데이트와 배포

- **GitHub Actions** 작업 하나가 다음 순서로 돈다: 동기화 → 빌드 → GitHub Pages 배포
  - 실행 시점: 1시간마다, 코드를 올릴 때, 그리고 **"Run workflow" 버튼**("지금 바로 업데이트")을 누를 때
  - 노션 내용이 지난번과 같으면(내용 해시 비교) 빌드와 배포를 건너뛴다
- 노션 연결 키는 GitHub 저장소의 **Secrets**(`NOTION_TOKEN`)에만 넣는다. 코드에는 넣지 않는다.
- 저장소는 **공개(public)** 로 만든다. 무료 계정의 GitHub Pages와 Actions를 제한 없이 쓰려면 공개여야 한다.
  공개되는 건 사이트 코드뿐이고, 노션 키는 Secrets에 있어 보이지 않는다.
- 주소: 처음에는 `https://<깃허브아이디>.github.io/` 를 쓴다. 개인 도메인은 나중에 연결할 수 있다(이번 범위 밖).

## 6. 문제가 생겼을 때

| 상황 | 동작 |
|---|---|
| 노션 연결 실패, 키 만료 | 그 회차의 작업이 실패로 끝나고 **이전 사이트가 그대로 유지된다**. GitHub에서 실패 알림 메일이 온다 |
| 이미지 하나를 못 받음 | 그 이미지만 빼고 계속 진행한다. 로그에 경고를 남긴다 |
| 노션에 모르는 블록 종류가 있음 | 그 블록은 건너뛴다. 로그에 블록 종류를 남긴다 |
| 영문 제목이 없음 | 4장의 규칙을 따른다 |
| 사용자 기기에서 WebGL이 안 됨 | 3D 대신 크롬 오브젝트 정지 이미지를 보여 준다 |
| "동작 줄이기" 설정 | 3D 회전과 카드 애니메이션을 끄고 정지 상태로 보여 준다 |

## 7. 기술 구성

- **Astro 5** (정적 사이트), TypeScript
- **Three.js**: Home의 크롬 오브젝트 하나에만 쓴다. 해당 화면에서만 불러온다.
  처음에는 코드로 만든 추상 형태를 쓰고, 나중에 Blender에서 내보낸 `.glb` 파일로 바꿀 수 있게 한다.
- **@notionhq/client**: 노션 공식 API
- **sharp**: 이미지 변환
- 테스트: **Vitest**(노션 → site.json 변환), **Playwright**(화면 확인)

### 폴더 구조
```
DESIGN.md                    디자인 규칙 (awesome-design-md 형식)
scripts/sync-notion.ts       노션 → site.json + media 실행 파일
src/lib/notion/fetch.ts      노션 API 호출 (네트워크만 담당)
src/lib/notion/map.ts        노션 데이터 → site.json 변환 (순수 함수, 테스트 대상)
src/lib/notion/media.ts      파일 다운로드와 변환
src/lib/site-schema.ts       site.json 타입 정의 (사이트와 스크립트가 공유)
src/data/site.json           동기화 결과 (첫 버전은 지금 확인한 노션 내용으로 채움)
src/components/              Nav, ChromeHero, CategoryList, WorkStack, BlockRenderer, …
src/pages/                   index, works/index, works/[slug], about
.github/workflows/deploy.yml 동기화·빌드·배포
```

## 8. 확인(테스트) 방법

1. **변환 테스트**: 노션 API 응답 예시를 고정 데이터로 두고, `map.ts`가 올바른 `site.json`을 만드는지 확인한다.
   영어 제목 규칙, 전화번호 제외, 모르는 블록 건너뛰기, 최신순 정렬을 포함한다.
2. **빌드 확인**: `npm run build` 가 경고 없이 끝나는지 본다.
3. **화면 확인**(Playwright): 데스크톱(1440px)과 휴대폰(390px)에서 네 화면을 연다.
   - 콘솔 에러가 없는지
   - 가로 스크롤이 생기지 않는지
   - Home의 메인 텍스트가 모두 영어인지
   - 연락처 링크가 동작하는지
   - 스크린샷을 찍어 사용자에게 보여 준다
4. **실제 연동 확인**: 사용자가 노션 키를 넣은 뒤 Actions를 한 번 돌려서, 노션 내용이 실제 사이트에 나오는지 본다.

## 9. 사용자가 할 일 (만드는 동안 단계별로 안내)

1. 노션 Projects 표에 **`영문 제목`** 칸(텍스트) 추가. 비워 둬도 된다.
2. 노션 **연결(Integration) 만들기** → 키 복사 → "JUWON's ARCHIVES" 페이지에 그 연결 추가
3. **GitHub 계정** 준비 → 저장소 Secrets에 `NOTION_TOKEN` 저장 → Pages 켜기

## 11. 구조 개편: 단계별로 깊어지는 구조 (2026-11-03, 사용자 승인)

AREA Technology의 **뎁스 구조**만 가져와요. 한 화면에 하나만 보여 주고, 클릭할 때마다 한 단계씩 깊어지는 방식이에요. 겉모습은 이 사이트의 것을 유지해요.
같은 날 함께 정한 것: 모든 게시물은 1280×720(16:9) 틀에 넣고, 인스타그램은 원본 파일로 재생하고, 이미지는 원래 크기보다 키우지 않아요.

| 단계 | 주소 | 화면 |
|---|---|---|
| 0 | `/` | **JUWON** + 부제 + 3D 오브젝트. 오른쪽 아래에 알약 버튼 `ARCHIVE` `INFO`만 둬요. 분야 목록은 없어요 |
| 1 | `/archive` | 분야마다 **크롬 3D 보관함**(CSS 3D 상자, 앞면에 커버 이미지)을 한 줄로 놓아요. 이름은 아래 mono 글씨. 휴대폰에서는 2열이에요. 마우스를 올리면 뚜껑이 살짝 열려요 |
| 1 | `/info` | 가운데 정렬. 부제, 경력, 툴, 연락처를 간결하게 보여 줘요. 전화번호는 계속 숨겨요 |
| 2 | `/archive/[slug]` | 위 바: `← ARCHIVE` · `JUWON` · `INFO` → 요약(번호, 영어 제목, 툴 태그, 링크) → `+ MORE INFO`(첫 미디어 앞에 있는 글을 접었다 펼쳐요) → 노션 구분선을 기준으로 `SECTION 01, 02…`. 각 미디어는 재단선 모서리가 있는 1280×720 틀 안에 둬요 |

- **섹션 나누기 규칙**: 노션 블록 중 첫 미디어나 첫 구분선 앞에 있는 글은 소개(MORE INFO)로 써요. 나머지는 구분선마다 섹션 하나가 돼요. 미디어도 글도 없는 빈 섹션은 버려요. 섹션 안의 첫 제목(노션 heading)은 섹션의 작은 부제로 보여 줘요.
- **예전 주소**: `/works`는 `/archive`로, `/works/[slug]`는 `/archive/[slug]`로, `/about`은 `/info`로 넘어가요. 이미 공유한 링크도 계속 열려요.
- **없어지는 것**: 대각선 카드(WORKS)와 홈의 분야 목록. 분야 목록에 마우스를 올리면 3D에 커버가 비치던 기능도 함께 없어져요.
- **3D 오브젝트 모양**은 후보를 보여 드리고 사용자가 고른 뒤에 바꿔요. 이 개편 범위에는 넣지 않아요.
